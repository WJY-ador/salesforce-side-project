# 2026.03.25 Issue Log: google-genai 패키지 및 .zshrc 오류 해결

> 📅 2026-03-25 정리

### 1. 시작포인트 (Starting point)
- `gemini` alias 실행 시 `google-genai` 패키지를 찾지 못하는 모듈 로드 문제 발생.
- `source ~/.zshrc` 수행 시 `command not found: n#` 에러가 발생하며 설정 파일이 정상적으로 로드되지 않음.

### 2. 과정 (Process)
- **환경 분석:** `which python3` 명령을 통해 alias가 시스템 Python(`/opt/homebrew/bin/python3`)을 호출하고 있음을 확인. 패키지는 `~/Desktop/Salesforce /Newbrick/gemini-env/bin/python3` 가상환경에만 설치된 상태.
- **구문 분석:** `.zshrc` 파일의 7번 줄에 실제 줄바꿈 대신 `\n` 리터럴 문자가 포함되어 셸이 이를 명령어로 오인하는 상황 식별.
- **해결 조치:** 
  1. `gemini` alias의 Python 경로를 가상환경의 절대 경로로 명시적 수정.
  2. `.zshrc`의 불필요한 `\n` 문자를 실제 줄바꿈으로 정리.

### 3. 챌린지 (Challenges)
- **환경 불일치:** 패키지가 설치된 가상환경과 alias가 바라보는 런타임 환경의 격리로 인해 "설치했음에도 찾지 못하는" 전형적인 환경 변수 문제에 직면.
- **파싱 에러의 연쇄 작용:** `.zshrc` 상단의 구문 오류로 인해 하단의 alias 수정 사항이 반영되지 않아 문제 해결 여부를 즉각 확인하기 어려웠음.

### 4. 결과 (Results)
- `gemini` 명령어가 가상환경의 `google-genai` 패키지를 정상적으로 로드하여 동작함.
- `source ~/.zshrc` 시 오류 없이 클린하게 로드되어 셸 환경이 안정화됨.

### 5. 느낀점 (Learnings/Reflections)
- **명시성(Explicitness):** CLI 도구나 자동화 스크립트에서 Python alias를 설정할 때는 가급적 가상환경의 절대 경로를 사용하는 것이 환경 격리 문제를 방지하는 최선책임.
- **정밀함(Precision):** 설정 파일 수정 시 보이지 않는 특수 문자나 잘못된 리터럴이 포함되지 않도록 에디터의 구문 강조 기능을 적극 활용해야 함.
